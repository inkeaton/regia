# Everything for Science – Demo Game

A demonstration game that showcases the Regia language in action.
The game is built in **Godot 4.7** and its NPCs are driven by AgentSpeak agents running on the **JaCaMo** multi-agent platform, through **VEsNA**'s framework, in **Java**. The two systems communicate in real-time over WebSockets.

The game scenario, _"Everything for Science"_, features a scientist, a cop, and a dog whose behaviours and narrative arcs are authored in Regia source files, compiled to AgentSpeak, and executed live inside JaCaMo.

## Running the Demo

Both the agent system and the game must be running simultaneously.

### 1. Start the Agent Minds

```bash
cd science_game/minds
./gradlew
```

This compiles the Java sources and launches the JaCaMo platform, loading the agent configuration from `science.jcm`. Each agent opens a WebSocket server on its configured port (9001–9004).

### 2. Start the Godot Game

Open `science_game/game/project.godot` in Godot 4.7, then press **F5** (or the Play button) to run the project.

The game's `vesnaManager.gd` connects to the agent WebSocket servers automatically. Once both systems are running, the NPCs begin executing their AgentSpeak plans.

## Recompiling the Regia Sources

The `.asl` files in `minds/src/agt/gen/` are generated by the Regia transpiler from the `.regia` files in `minds/src/regia/`. To regenerate them:

```bash
source .venv/bin/activate
regia compile science_game/minds/src/regia/for_science.regia -o science_game/minds/src/agt/gen/
```

## Changing Ports

Each agent communicates with its Godot NPC body over a dedicated WebSocket connection. The port must match on both sides:

| Agent | Default Port | JaCaMo config | Godot config |
|---|---|---|---|
| Scientist | `9001` | `science.jcm` → `port` field | Scene Inspector → VesnaManager → `PORT` property |
| Cop | `9002` | `science.jcm` → `port` field | Scene Inspector → VesnaManager → `PORT` property |
| Dog | `9003` | `science.jcm` → `port` field | Scene Inspector → VesnaManager → `PORT` property |
| Director | `9004` | `science.jcm` → `port` field | _(no Godot body)_ |

**JaCaMo side** — edit [`minds/science.jcm`](minds/science.jcm) and change the `port:` value for the relevant agent.

**Godot side** — each NPC node has a `VesnaManager` child with an exported `PORT` property. Change it either:
- In the **Godot Inspector** panel (select the NPC node → VesnaManager → PORT), or
- Directly in the `.tscn` scene file (e.g. `PORT = 9001`).

> **Note:** The VesnaManager default in [`libraries/vesnaManager.gd`](game/libraries/vesnaManager.gd) is `9080`, but each NPC scene overrides it. If you add a new agent, make sure both the `.jcm` and the scene agree on the same port.
