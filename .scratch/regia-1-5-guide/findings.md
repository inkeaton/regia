# Findings

Spec contradictions, gaps and glossary problems found while working the *Regia 1.5 showcase and guide* map. One line each: what, where, and the ticket that found it. Fixing them is a later spec effort, unless one blocks a chapter.


- The Quota quantity writes `n OF` as `of(k)` (chapter 33, *Quantity*), while `regia.pick` writes it as `count(N)` (chapters 35, 39); `n% OF` is `share(…)` in both since *Rename generated ASL names built on retired words*. One of the two should give way. Quotas are 2.0 only, so it doesn't block a 1.5 chapter.
- Chapter 21, *Agent kinds*: "With no Body, the header ends with `.`" is a rule from before the syntax review; a trailing `.` is silent now (chapter 01), and the chapter's own examples (`KIND servant, PLAYS Servant`) write none. Found by *Bring the showcase to the 1.5 syntax*.
- Trailing `.` is still written in some spec examples and inline quotes (about 17 quotes such as `DO clear_tables.` in chapter 30 and `DROP strike.` in chapter 40, and code in chapter 38, lines 12–16 and 94), against chapter 01's "no trailing `.`" default. Harmless, since the dot is silent. Found by *Bring the showcase to the 1.5 syntax*.
- Chapter 02, *Transpiler checks*: `R0201` is "an unclosed multiline comment", but the chapter calls only `#[ … ]#` a multiline comment; whether an unclosed `#@key[` (a multiline Doc comment) is also `R0201` isn't said. The guide reads it as yes. Found by *Write guide chapter 02, Syntax*.
- Chapter 10, *What the game produces*, says `GAME` goes on `FACT` and `CUE` only, but `R1016` lists only `GOAL`, `ACTION`, `NAME` and local declarations: `GAME TRAIT` / `GAME MOOD` has no code. Found by *Write guide chapter 03, Vocabulary and files*.
- Chapter 03, *Names are declared*: "Agent names are never Names", while chapter 21, *Individual Agents*, calls an Agent's name "a Name inside Instancing" that a Plan "meets at runtime as an ordinary Name". The two should use one wording; the guide follows chapter 21. Found by *Write guide chapter 03, Vocabulary and files*.
- `GLOSSARY.md`: *Vocabulary* lists Facts, Cues, Actions, Goals and Propensities and doesn't say whether declared Names belong to it; and *Mood* ends with a stray second line, `_Avoid_: Notification, message`, apparently left from a removed entry. Found by *Write guide chapter 03, Vocabulary and files*.
- Chapter 10, `R1005`, lists kind, parameter count and External name; the text above it (*What the game produces*) adds disagreeing on `GAME`. The check's line should name `GAME` too. Found by *Write guide chapter 03, Vocabulary and files*.
- A Role name used as a Value has two codes: `R0303` (chapter 03) and `R1501` (chapter 15, "as an argument or in an Expression"). One should give way; the guide uses `R0303`. Found by *Write guide chapter 05, Placeholders and Expressions*.
- Chapter 04, *Branches*, and chapter 09, *Placeholders in an Option*: a Placeholder filled by `LET` in only some `IF` branches or Options, used after them, is an error with no code. `R0305` ("isn't certainly filled") names only `NOT` and `OR`. The guide reads it as `R0305`. Found by *Write guide chapter 05, Placeholders and Expressions*.
- Chapter 03, *"Don't care": `?`*: "These are the only cases the writer can't fix with `?`" follows one spared case (a Trigger Placeholder some `GIVEN` siblings use) and one that is not spared (a `GIVEN`'s own Placeholder, checked in its Block alone). The guide reads it as one case. Found by *Write guide chapter 05, Placeholders and Expressions*.
- Chapter 04, `R0404`: "a comparison in a Context" with an unfilled side; the same holds in an `IF` condition (chapter 06 writes both alike), and the check's line doesn't say so. Found by *Write guide chapter 05, Placeholders and Expressions*.
- Chapter 26, *A weighted Pick*: "Wrong Weights follow chapter 09", but it doesn't say whether a negative Match Weight writes `T0902`, as a negative Option Weight does. Chapter 39 clamps it in `regia.weighted_pick` with no entry. Nor does it say whether `T2601` is written when Weights that aren't Numbers leave a `GIVEN` with no Match. The guide names neither. Found by *Write guide chapter 06, Matching*.
- Chapter 26, *`COUNT`*: "There is no `GIVEN 3 OF …`" has no code, and the Transpiler checks don't list it. Found by *Write guide chapter 06, Matching*.
- Chapter 08, `R0805`: "a trailing clause … on a Statement other than `PURSUE` and `DO`" doesn't except `WAIT d, UNTIL c` (chapter 12), whose `UNTIL` is written after a `,` like a trailing clause. Either chapter 12 says `, UNTIL` is part of `WAIT`'s own form, or `R0805` names it. The guide treats it as `WAIT`'s own form. Found by *Write guide chapter 07, Actions and time*.
- Chapter 37, *The game's replies*: the `walk_to` example writes its doc comment as `## …` lines, which chapter 02 makes plain comments; it should be `#@desc:`. Found by *Write guide chapter 07, Actions and time*.
- Chapter 34, *Trace codes*, lists `T0902` and `T0903` under "Runtime warnings", while chapter 09, *Trace entries*, says "Neither is a warning: both can be meant." The same table also leaves out `T2601` (chapter 26), which is likewise an entry and not a warning. The guide follows chapter 09. Found by *Write guide chapter 08, Randomness*.
- Chapter 21, *Agent kinds*: the example `bravery AT RANDOM(-1, 1)` gives a Trait (chapter 14 declares `TRAIT bravery`) a range from -1, which `R2107` rejects. A Mood such as `aggressiveness` fits the point. The guide uses `aggressiveness`. Found by *Write guide chapter 08, Randomness*.
- Chapter 21, *The seed*, says `SEED` exists "so that a run can be played again", but only a behaviour case runs its Agents in lockstep (chapter 34). Whether a free run with the same seed draws the same way, given thread timing, isn't said. The guide promises it for cases only. Found by *Write guide chapter 08, Randomness*.
- Chapter 11, *Trace entries*, lists `T1102` (`PURSUE g` waiting on a Goal that fails) as a Failure cause, and chapter 34's table repeats it. But chapter 34, *The failure chain*, writes one `failure` entry per Failure, for the original cause, and each Goal up the chain as a `GOAL … FAILED because #<seq>` entry, so nothing ever writes `T1102`. Either `T1102` is retired or the chain says when it is written. The guide follows the chain and doesn't list `T1102`. Found by *Write guide chapter 09, Goals and Failure*.
- Chapter 34, *What the Trace records*: the `fact` row says "its own `REMEMBER`/`FORGET`/`UPDATE`". `REMEMBER` isn't a Regia word (it's `LEARN`), and it isn't in chapter 01's retired table either. Found by *Write guide chapter 09, Goals and Failure*.
- Chapter 15, *Leaving Agents out*: "the list ends at the first word that can't be an item: `TO` in `MAPPING Guest EXCEPT ?a, ?b AS Spectator`" names `TO`, left from the retired `MAPPING a TO b`; the word is `AS`. Found by *Write guide chapter 11, Playbooks and Roles*.
- Chapter 15, *Playbook Roles*: "`ROLE` lines come before the Playbook's Trigger Blocks" has no code, and chapter 10 lets local declarations go anywhere in the Block. Either a `ROLE` line after a Trigger Block is an error with a code, or the order is a convention. The guide states the rule without a code. Found by *Write guide chapter 11, Playbooks and Roles*.
- Chapter 20, `R2005`: "`ENTERED`, `EXITED` or `ENDED` in a Playbook" doesn't say which `ENDED`; a Playbook writes `WHEN take_seat ENDED` for a Goal. The guide lists only `ENTERED` and `EXITED` under `R2005`. Found by *Write guide chapter 11, Playbooks and Roles*.
- Chapter 15, *Odd values*: a count that isn't a Number "fails the Plan" (`T1501`), while chapter 20 says Director Statements never fail. Chapter 11 says a failing Director Plan stops and leaves its Phase and Staging untouched, which the guide follows for a Director's `ASSIGN … TO ?n OF Guest`, but chapter 15 doesn't say that the Director case is meant. Found by *Write guide chapter 11, Playbooks and Roles*.
- Chapter 20, *Failure*: a failing Director Plan "stops there", and the Phase and the Staging are untouched, but nothing says what a failing `EXITED` Plan does to the transition it runs inside (`ENTER`'s step 2, or `END PLOT`). The guide reads it as "the Plan stops and the transition goes on". Found by *Write guide chapter 12, Plots and Directors*.
- Chapter 17, *Casting*: "Instancing names or infers the Root (chapter 21)" still allows an inferred Root Plot, while chapter 21, *The Root Plot*, says it is "named, never inferred" (ADR 0036). The guide follows chapter 21. Found by *Write guide chapter 12, Plots and Directors*.
- Chapter 20, *Declaring Phases*: "any `ENTER` in [a Plot with no Phases] is an error" has no code of its own. The guide lists it under `R2008` (a Phase the Plot doesn't declare). Found by *Write guide chapter 12, Plots and Directors*.
- Showcase `README.md`, *Coverage* for chapters 03 and 17: "a Plot parameter in `pl/honor_duel` (`?offender`)" and "`?offender` used inside it", but `HonorDuel` never reads `?offender`; the parameter only tells the Stagings apart in `RoyalBanquet`. Either the README says so or the duel uses it (for example in a Role setup). The guide shows the use in a throwaway variation. Found by *Write guide chapter 13, Subplots and Stagings*.
- `EMPTIED` for a Role that starts empty: chapters 17 (*Casting*) and 19 put it "after the Role setups and before the initial Phase's entry Plans", but chapter 20, *What starting a Staging does*, leaves it out of its steps, and none says whether it comes before or after `DURING PLOT`'s `ENTERED`. The guide puts it after the setups and before both `ENTERED` Plans. Found by *Write guide chapter 13, Subplots and Stagings*.
- Chapter 17, *Outcomes*: "A local Cue of a Playbook can't be an Outcome" has no code; `R1703` ("something other than one declared Cue") may or may not cover a Cue that isn't visible in the Plot (`R1004`). The guide states the rule without a code. Found by *Write guide chapter 13, Subplots and Stagings*.
- Chapter 19, *The Director hears about it*: "a Director can give [`?who`] a Playbook or map it onto a Role" is said of `?who` in general, but *Not decided here* says `?who` from `LEFT` "is only a dropped recipient". Nothing says what `ASSIGN P TO ?who` or `MAPPING ?who AS r` does with a leaver, or which code it writes (`T1506`?). The guide says only that `?g` holds the leaver as a Value and that a Message to it is `T1901`. Found by *Write guide chapter 14, When an Agent leaves*.
- Chapter 19, *Order when leaving*, orders the Triggers inside one Staging only. When a leaver played in several Stagings (a Defender is also a Guest), nothing says in which order the Directors hear it, or whether a Subplot's `END PLOT` from its `EMPTIED` Plan can reach the parent before the parent's own `LEFT`. The guide draws the two without an order. Found by *Write guide chapter 14, When an Agent leaves*.
- Chapter 38, *The Interface of a Playbook*: the table's row reads "every `WHEN` Trigger with a `FROM`", while the next line says "A Trigger with no `FROM` is listed as open to anyone". It isn't said whether a `WHEN` Trigger with no `FROM` (`WHEN saw_pouring(?who):`, `WHEN idle:`) is listed. The guide lists a recipe with no `FROM` as open to anyone and leaves out `WHEN` Triggers with no `FROM`. Found by *Write guide chapter 15, Interfaces*.
- Chapter 38, *The Interface of a Plot*: "The Signals it handles" is read from "every `WHEN e` Plan", which takes in a game Cue heard with no `FROM` (`Poisoning`'s `WHEN poison_drunk:`) as if it were a Signal. Either the row is limited to Cues that some `SIGNAL` sends, or it says that game Cues are listed too. The guide's example, `HonorDuel`, has no such Plan. Found by *Write guide chapter 15, Interfaces*.
- Chapter 38, `R3802`, names `WHEN e, FROM <Role>` only. - Chapters 23 and 38 don't say how `regia explain <entry> interface` prints an Interface (its layout, how a local Cue is "listed with the Playbook's own name beside it"), and the showcase `README.md`'s *Coverage* for chapter 38 places the printed Interfaces in `runs/evening` and `runs/two_duels`, which don't exist yet.
