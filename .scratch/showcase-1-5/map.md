# Map: The Regia 1.5 showcase and its Jason translation

Label: wayfinder:map

## Destination

A showcase Program in Regia 1.5 in `docs/showcase/`, which a 1.5 build would accept with no `R0109`. Beside it, decided outlines for two guides: its walkthrough, and a Jason showcase (a full hand-written reference Build in `docs/showcase/jason/`, plus a guide that goes from each feature's Regia source to the Jason it becomes). Every Jason translation question the reference Build raises is decided and carried into spec chapters 28–37. The two guides, and the reference Build's files, are then written as hand-off work.

Charted with the user on 2026-11-17.

## Notes

- **Plan, with one exception.** Tickets decide; they don't write the guides or the reference Build. The one exception is the 1.5 showcase Program itself, written inside the map (*Write the 1.5 showcase Program*), because the coverage and the Jason questions can only be checked against it.
- **Strictly 1.5.** The Program uses only what is in Regia 1.5 (ADR 0025; every spec chapter's `## Regia 1.5` section; the index in chapter 27). Where a 1.5 pattern stands in for a 2.0 construct (hand counting instead of a Quota, a Signal back instead of `BY`), the guide adds a short "In 2.0" note. It shows no 2.0 code.
- **Same world.** The royal banquet of the old showcase (`docs/guide/showcase/`), reworked for 1.5. The old showcase is source material and isn't edited: its README's *Coverage*, *Interactions the world forces*, *Review notes* and *Gaps in the showcase* are inputs. The old guide chapters 18 (*Translation to ASL*) and 19 (*Showcase*) are source material for the two outlines.
- **The spec wins.** The showcase is derived from the spec. Where they disagree, either the showcase is fixed or a decision ticket changes the spec. Jason decisions close only when chapters 28–37 are edited, as on the revision map.
- **Later use.** The guide chapters (0–17, 20) are rewritten in a later effort, with the new showcase and the Jason files as reference material. Name things here so that they can be quoted there.
- Tickets: `.scratch/showcase-1-5/issues/NN-<slug>.md`, with `Type:`, `Status:`, `Assignee:` and `Blocked by:` lines. The frontier is the open, unblocked, unclaimed tickets, lowest number first.
- Skills: `grilling` and `domain-modeling` for every grilling ticket; `prototype` for prototype tickets. The memories *Language vs game design* and *Playbooks decide, Plots nudge* hold for the showcase's design too.

- [What the Jason chapters leave open](issues/05-jason-open-questions.md): an [inventory](jason-open-questions.md) of what a Jason reference Build of the showcase hits and the spec doesn't answer, with chapters and showcase lines, in thirteen groups that became tickets 10–22. Chapter 31 is behind ADR 0030, chapter 29 behind ADR 0021, and chapter 14's Moods disagree with VEsNA-Pro's range.
- [Leaving two Agents out of one Role](issues/07-two-exceptions.md): `EXCEPT` takes a comma list of Roles and Placeholders, in 1.5 and 2.0 (chapter 15, `R1510`). `RoyalBanquet` maps `Guest EXCEPT ?offended, ?offender TO Spectator`, so the Defender is no Spectator and `HonorDuel` has no `EXCEPT`; a Giving and a recipient with `EXCEPT` are snippets.
- [How Jason behaves where the translation waits](issues/10-jason-facts.md): six Jason and `Temper` facts, sourced on branch `research/jason-facts`. A suspended `[atomic]` intention blocks everything until Java wakes it; a `-!g` plan with a false context drops the whole intention; `.fail(…)` arguments can carry a Reason; `Temper` takes Moods in [-1, 1] and applies `effects` only to a contested choice; `regia.shift` needs a VEsNA-Pro change.
- [The Jason showcase's shape](issues/06-jason-showcase-shape.md): one reference Build, of `banquet.regin`, in `docs/showcase/jason/banquet/`, laid out as chapter 28's Build folder so a real build can be diffed against it; runs shown as cast diffs. The guide (`jason/README.md`) goes feature by feature, and is found through a new **Jason** column in the coverage table. The old small `evening` Build and *Since 1.0* are dropped. `.trace` excerpts sit beside the ASL that writes them. The [decided outline](prototypes/jason-showcase-outline.md) holds the detail.
- [What counts as using a Placeholder](issues/08-using-a-placeholder.md): a Pick, a join, and any `GIVEN` Block under a shared Trigger count as using a Placeholder (chapters 03, 06, 26). The laughing alternative writes `?_who`, so the showcase has no allowed warning, and `#@allow` is a snippet.
- [Scripting the game for one Agent](issues/09-scripting-one-agent.md): a `cue`/`fact` step names its receiver first, as the Trace writes it (`> cue noble_2 idle`, `> cue director:Banquet poison_drunk`); `*` reaches every body that uses the item; a step with no receiver, or one naming an absent Agent, is a case error. Chapters 34 and 35 and the two existing cases are updated.
- [A Plan's Statements in ASL](issues/11-statements-in-asl.md): a new chapter 39, *Plan bodies in Jason*, holds the Statement translations, and the language chapters keep only Target-neutral notes. `?speaker` → `Speaker`, generated variables `Regia_…`, and `R1007`/`R1008` now cover Placeholders. `FOR EACH` is a `.setof` snapshot plus `for`. `regia.wait(Cond[, D])` is tested on every event, never fails on timeout, and writes its own `time` entry. `regia_if`/`regia_either` were dropped from the Jason chapters.
- [Messages and told Facts in ASL](issues/12-messages-in-asl.md): a told Cue and a Signal are Jason `signal` messages, which leave no belief; Sender forms test the trigger's `source`; per-Cue `regia_unheard` catch-alls write `T0702`/`T3801` when no Plan ran; `brf` raises `+f` only for a new Fact (first teller), and `FORGET` is `.abolish`; `ME` is `.my_name`. In chapter 39's *Messages* and chapter 30's *Signals*.
- [A Goal's life in ASL](issues/13-goal-life-in-asl.md): a new chapter 40. Each Pursuit carries `regia_pursuit(Id)` (the `seq` of its `PURSUED` entry). Endings are plans for generated `regia_<kind>` goals, with a `regia_noop` fallback. `REACHED` runs on a new intention; `FAILED` runs in-line in one unguarded `-!g` per Goal, which fails again with `regia_reason`/`regia_because`. `DROP` and `stop_playbook` share a Java walker. `PURSUING` is `regia.pursuing(G, Except)`. Each Failure has exactly one cause entry.
- [Roles an Agent reads](issues/14-roles-an-agent-reads.md): one rule, `regia_plays(P, R, A)`, reads a Playbook Role for `TELL`, `PLAYS`, `FROM` and Quotas, and `regia_plays(R, A)` does the same on a Director (always through `.setof`). A counted recipient is drawn by `regia.pick` from the pool without the sender, rounding a share up, and the Director's picks use the same draw. `MAPPING ?who` reaches like `ASSIGN TO ?who`, so `king` gets a `temper`. In chapters 29, 30 and 39.
- [Exclusions, one Agent and a Phase in the Giving record](issues/15-giving-record.md): `regia_given` gains `Until` (`staging` or `phase(Ph)`) and a `role(cast)` target. `EXCEPT` travels as `live(Role, Except)`, and on the Director it is read by `regia_reach`. `FROM Guest ?who` sets Givings aside (`regia_aside`) so that `TO Guest ?who` can restore them. `FROM ?who` takes only Givings made to that Agent. `regia_standing` gains `Except` and `Until`, and `TRANSITION` sends `regia_take_phase`. In chapters 29 and 30.
- [A Playbook's opening and closing in ASL](issues/16-opening-and-closing.md): `regia_give`/`regia_restore` post `!!regia_assigned(P)` on a first Giving. Each take step snapshots the lost Givings as `regia_closing(C, …)` and runs one closing intention: the drops' endings, then `UNASSIGNED` in name order, then `ASSIGNED` for anything given back. The ending goals gain a `Closing` argument for the guard, and readers go through `regia_holds`. A live binding through an ended Staging reaches nobody, and `T2902` is retired. Chapter 29 is rewritten, with chapter 40's signatures changed.
- [What a Staging runs when it starts](issues/17-staging-start.md): Director files carry `regia_initial_phase` and `regia_roles`. Setups are one Goal, `regia_setup(Scope, Role, A)`, run by a fixed `regia_run_setups(Scope)`: `CAST`, then the Roles, then the initial Phase's. The Root then runs the kind and individual lines (`regia_instance_setup`, `LIKE` resolved at compile time, so `percival` has no grudge), then posts `EMPTIED` for empty Roles, then `ENTERED`, each starting first. Setup Givings aren't standing. `regia_start_cast` is `[agent(A, Source, Roles), …]`. In chapters 30, 31, 33 and 36.
- [Entering and leaving a Phase in ASL](issues/18-phase-change.md): `TRANSITION` has seven atomic steps, with setups after the Phase change and before `ENTERED`. `regia_child` gains `Until`, and `UNTIL EXITED` children are ended at step 3, whose `dropped` starts first under the new Phase. Each `AFTER` is a numbered `regia_after(Scope, N)` that waits with `regia.wait` and tests its Context when the time is up. `stop_phase` drops queued entry events. `IN` is `regia_phase(p)`. A waiting `DO` in `EXITED` is allowed: the Director holds still, and a Subplot's `regia.act` wakes from a Java listener. In chapter 30.
- [Subplot arguments and endings in ASL](issues/19-subplot-endings.md): `regia_start` carries `Args`, kept as `regia_args` and read in the contexts that name a parameter. `regia_child` gains `Args`, which `RUNNING` and `END SUBPLOT`'s pattern read. Every ending runs one `regia_subplot_endings` intention: the specific goal, then `regia_subplot_ended`, to completion, with `Heard` out-arguments for `T3802`. `regia.end_body` ends only its own Plan. `regia_end` means `BY PARENT`. In chapter 31. (Its unguarded Root Action relay was later replaced: every Director sends its own Actions through the game link, chapter 37.)
- [Moods and Labels on VEsNA-Pro](issues/20-moods-on-vesna.md): negative Moods already work. A `SHIFTS` Label applies once, when its Plan is chosen (`R1410` retired), and stays an `effects` annotation that `RegiaAgent.selectOption` applies through `Temper.shift`. `selectIntention` is Jason's round-robin. An upstream patch adds `getTemper`, `Temper.shift` and fixed `random` weights, and moves to JaCaMo 1.3.1 / Jason 3.3.2.
- [The Target's own code in a Build](issues/21-target-code.md): dotted Actions' Java is jarred by the writer into the Project's `lib/`, which `regia run` and `regia test` put on the class path. A dotted Action goes through `regia.act`, which runs the class itself and writes both `DO` entries. A missing class fails at run time. `> action` rules script only game Actions. The reference source is `docs/showcase/java/hall/music/fanfare.java`. Chapter 37's stale call-off line is deleted.
- [The Trace's fields and entries](issues/22-trace-pieces.md): the `plan` entry is written at selection by the agent class, with `by` (`GIVEN`/`ELSE` dropped), `over`, `fits`, and `mood` entries after it. A Failure has one coded `failure` cause, and each level that fails writes `GOAL`/`PLAN … FAILED` at `error`. Agents write their `GIVE`/`TAKE` per Giving, `IN <director>`. `SIGNAL` and setup `LEARN`/`PURSUE` are `message` entries. A Staging's start writes `STAGING`, `PHASE -> x`, then its Facts. The writer numbers Stagings and works out `ALSO IN` from its own entries. Agent names are fixed in chapter 34. Chapter 34 has a per-kind field table, and `sourcemap.json` has `lines`, `names` and `plans`.
