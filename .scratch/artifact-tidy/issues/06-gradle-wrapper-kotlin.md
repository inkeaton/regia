## Question

How does `science_game/minds` build with a pinned Gradle and a pinned JDK, whatever happens to be installed?

Steps:

1. Generate the wrapper (latest Gradle 9.x) and commit `gradlew`, `gradlew.bat` and `gradle/wrapper/`.
2. Convert `build.gradle` to `settings.gradle.kts` and `build.gradle.kts`.
3. Set a Java toolchain of 21, with the foojay resolver plugin in settings so JDK 21 is downloaded when missing. The author's machine has JDK 27, which makes it a good test.
4. Keep the `run` task as the default, with the same behaviour.

`./gradlew classes` must pass. In the README, replace "wrapper included" and the bare `./gradlew` with the real commands.

## Resolution (2026-11-24)

Done. `1.0` is now at **`a68d387` "Build the minds with the Gradle 9.9.2 wrapper and a JDK 21 toolchain"** (anonymous, no trailer), on top of `5a81bca`. **Not pushed.** Committed in the `1.0/` worktree.

- **Wrapper:** Gradle **9.9.2** (the latest 9.x on 2026-11-24, per services.gradle.org), `bin` distribution, with `distributionSha256Sum` pinned. The wrapper jar was regenerated by 9.9.2 itself. Committed files: `gradlew`, `gradlew.bat` (CRLF, as Gradle writes it; there's no `.gitattributes`) and `gradle/wrapper/`.
- **Kotlin DSL:** `build.gradle` → `build.gradle.kts` (via `git mv`) plus a new `settings.gradle.kts` (`rootProject.name = "science-minds"`, plugin `org.gradle.toolchains.foojay-resolver-convention` **1.0.0**). Repositories, dependencies (jacamo 1.2, Java-WebSocket 1.5.6, org.json 20230227) and `srcDir("src/")` are unchanged.
- **Toolchain:** `java.toolchain.languageVersion = 21`. The `run` task also gets `javaLauncher = launcherFor(toolchain)`, so JaCaMo runs on 21, not on whatever JDK launched Gradle.
- **`run`** is still the default task, with the same main class, args, stdout/stderr and logging system property. One addition: `doFirst { mkdirs("logs") }`. `logging.properties` has a FileHandler writing `logs/jason_log…`, and in a fresh clone (the snapshot too) it printed a `NoSuchFileException` stack trace at startup. The trace was harmless but noisy. `logs/` is already gitignored.
- **README** (`science_game/README.md`): the requirements row now reads "JDK ≥ 17 to run Gradle; build uses or downloads JDK 21; Gradle comes with the wrapper". The tree lists `build.gradle.kts`, `settings.gradle.kts` and `gradlew`. The run section shows `./gradlew` / `gradlew.bat`, `./gradlew classes`, and what the first run downloads.

**Checks** (on the author's machine: default `java` = JDK 27, no system `gradle`):
- `./gradlew classes` passes with the launcher and daemon on JDK 27. The class files are major version 65 (Java 21), compiled with the installed Arch JDK 21.
- With `-Porg.gradle.java.installations.auto-detect=false -Porg.gradle.java.installations.fromEnv=`, `./gradlew clean classes` makes foojay download **Temurin 21.0.13** into `~/.gradle/jdks`, and the build passes. Only that run printed a deprecation notice, and it came from the detection flags. A normal build with `--warning-mode all` shows none.
- `./gradlew` (the default `run`) starts JaCaMo (RTS, mind inspector, CArtAgO HTTP), and the VesnaAgents start up. With no Godot running, they get "connection refused" and kill themselves, which is expected. With the `logs/` fix, the log handler error is gone.

### Facts for later tickets

- **README pass (12): the start order is wrong.** In `vesnaManager.gd`, Godot is the WebSocket **server** (`TCPServer.listen(PORT)`), and `VesnaAgent` is a **client** (`WsClient extends WebSocketClient`). If the minds start first, as the README says, every agent gets "connection refused" and kills itself. The README should start Godot first and change "each agent opens a WebSocket server" to "connects to its body's port". It also needs to say what the director on port 9004 connects to, since it has no Godot body. This needs checking before rewriting.
- **Runtime benchmarks (09):** `language/benchmarks/runtime/jcm_generator.py` writes its own Groovy `build.gradle` for the benchmark MAS. If 09 runs that through `science_game/minds/gradlew` (or a copy of the wrapper), the generated build either needs a JDK 21 toolchain too or has to be run with `-p`/wrapper pointing at it.
- **Generated agents (07/08):** `science.jcm` loads `gen/director_forscience.asl`, and that path resolves under `src/agt/` through JaCaMo's default asl-path. `sourceSets.main.java.srcDir("src/")` is unchanged, so 08 can hook `compileJava`/`run` onto an Exec task in `build.gradle.kts`.
- **CI (13):** `actions/setup-java` with 21 plus `gradle/actions/setup-gradle` will satisfy the toolchain without a download. The wrapper checksum is pinned, so a wrapper-validation step is cheap to add.
- **Makefile (11):** the minds target is `cd science_game/minds && ./gradlew classes`. `./gradlew` alone blocks, because it runs the MAS.
