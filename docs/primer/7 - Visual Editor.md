While regia code can be written everywhere, a visual editor provides both tools and visualisations to better understand the code. In particular, synced edits between the source and the visualisation allows the user to speed up the writing process and edit in a more natural way, enhancing accessibility. 

The 1.0 editor was implemented as a React web application. This choice was made for two main reasons. First, the usage of a web app allows fro portability, allowing to embed the tool into other applications if needed, while still allowing for a standalone app using frameworks such as Tauri. Moreover, this enables the use of libraries which reduce the implementation work. in particular, Monaco is used as the text editor, with most editing features already implemented, and react flow is used to create the visualisation.

The application is designed to work in tandem with the transpiler. The source is written on the editor. The text is sent to the transpiler over an HTTP connection for compilation. The transpiler outputs the AST or its compilation error, and sends it to the web application. Here, the AST is rendered as a graph, or the resulting compilation errors are displayed inside of the editor. Edits on the canvas are a bit more tricky. Since we are working with an AST, we could not directly edit it and render it into text: we would be losing the comments and spacing set by the user.
