# Regia v0.2 = Language Specification

## 1. Keywords

| Keyword | Context | Purpose |
|---|---|---|
| `ACTION` | Element declaration | Declare a named action |
| `EVENT` | Element declaration | Declare a named event |
| `FACT` | Element declaration | Declare a belief/information |
| `SELF` | Event origin | Event generated by the agent itself |
| `ENVIRONMENT` | Event origin | Event from the game world (default) |
| `IMPORT` | File header | Include declarations from another file |
| `PLAYBOOK` | Top-level definition | Define a reusable behaviour set |
| `PLOT` | Top-level definition | Define a narrative scenario |
| `PHASE` | Plot header | Declare a phase within a Plot |
| `INITIAL` | Phase modifier | Mark the starting phase |
| `ROLE` | Plot header | Declare a role template |
| `DURING` | Plot body | Begin a phase behaviour block |
| `TRANSITION` | During block | Define a phase transition |
| `TO` | Transition | Target phase |
| `ON` | During block | Begin a phase boundary hook |
| `ENTER` | Boundary hook | Fires when entering a phase |
| `EXIT` | Boundary hook | Fires when leaving a phase |
| `WHEN` | Playbook / Plot | Reactive plan trigger (event name) |
| `IF` | Branch | Conditional guard (over FACTs) |
| `ELSE` | Branch | Fallback when no IF matches |
| `AND` / `OR` / `NOT` | Condition | Boolean operators over FACTs |
| `DO` | Action | Execute an action |
| `WORLD` | Plot action | Ownerless action (Director executes) |
| `SIGNAL` | Playbook action | Signal the Director |
| `ASSIGN` | Imperative stmt | Assign a Playbook to a Role |
| `UNASSIGN` | Imperative stmt | Remove a Playbook from a Role |
| `FROM` | Unassign | Source role |
| `PRIORITY` | WHEN block | Per-plan numeric priority |
| `TELL` | Special DO action | Send message to a specific agent |
| `BROADCAST` | Special DO action | Send message to all agents |
| `ACHIEVE` | Special DO action | Add a subgoal |
| `BELIEVE` | Special DO action | Add a belief |
| `FORGET` | Special DO action | Remove a belief |

## 2. Concepts

### 2.1 File Imports and Doc Comments

Regia source files can import declarations from other files and include structured documentation comments.

**Imports:**
Must appear at the very top of the file. Allows splitting base elements (Actions, Events, Facts) across files. The compiler resolves the import graph and merges declarations into a single program.

```regia
IMPORT "base_vocabulary.regia".
IMPORT "npc_actions.regia".
```

**Doc Comments:**
Special comments starting with `#@key: value`. These are extracted by the preprocessor and attached to the immediately following AST node (Playbook, Plot, Action, Event, or Fact). If they appear before any declarations, they are treated as file-level documentation.

```regia
#@author: Game Design Team
#@desc: Core combat playbook for aggressive enemies.
PLAYBOOK AggressiveEnemy:
    ...
```

### 2.2 Base Elements

Shared vocabulary used by Playbooks and Plots. Declared at the top of the file.

```regia
ACTION greet_back.
ACTION give_item(item, target).        # with parameter slots

EVENT fan_greets.
EVENT internal_check SELF.             # origin is optional (default: ENVIRONMENT)

FACT happy.
FACT has_item(item).                   # parameterised belief
```

### 2.2 Playbooks

Reusable, context-free bundles of reactive plans. Assigned to and removed from agents at runtime. Contain only self-directed actions and signals to the Director.

```regia
PLAYBOOK SingerInBackstage:

    WHEN fan_greets:
        IF happy:
            DO greet_back.
        IF angry:
            DO curse.
        ELSE:
            DO ignore.

    WHEN player_asks_about_quest PRIORITY 7:
        DO TELL(player, busy_message).

    WHEN attacked:
        DO flee.
        SIGNAL emergency.
```

**Constraints:**
- Only `DO` (self-directed) and `SIGNAL` (to Director) statements
- Cannot reference Plot-specific state (phases, active plots, roles)
- Can reference any globally-declared Action, Event, or Fact
- Plans carry optional per-plan `PRIORITY` (numeric)

### 2.3 Plots

Narrative scenarios written from a director-centric perspective. Use Roles (templates), not named agents. Each active Plot spawns its own Director agent at runtime.

```regia
PLOT Concert.

    PHASE backstage INITIAL.
    PHASE performing.

    ROLE Singer.
    ROLE AudienceMember.

    DURING PLOT:
        WHEN emergency PRIORITY 9:
            WORLD DO trigger_alarm.

    DURING backstage:

        TRANSITION TO performing WHEN time_to_start.
        TRANSITION TO cancelled WHEN cancelled_event IF NOT audience_present.

        ON ENTER:
            ASSIGN SingerInBackstage TO Singer.
            WORLD DO add_waiting_for_concert.

        ON EXIT:
            UNASSIGN SingerInBackstage FROM Singer.
            WORLD DO announce_concert.

        WHEN fan_rushes_stage:
            WORLD DO alert_security.
            Singer DO flee.
            AudienceMember DO ACHIEVE(find_exit).
```

**Key constructs:**
- `PHASE name INITIAL.` = declare phase; `INITIAL` marks the starting phase
- `ROLE name.` = declare a role template (bound to agent instances externally)
- `DURING phaseName:` = behaviour active only during that phase
- `DURING PLOT:` = behaviour active in all phases
- `TRANSITION TO phase WHEN event.` = event-triggered phase change (declarative)
- `TRANSITION TO phase WHEN event IF condition.` = declarative with guard
- `ON ENTER:` / `ON EXIT:` = imperative sequences at phase boundaries
- `WHEN event:` = reactive plan (director-centric)

**Inline Phase Transitions:**
Instead of declarative transitions, you can trigger a transition directly inside a `WHEN` block's imperative body using `TRANSITION TO phase.`. This must be the **last statement** in the block or branch, and is not allowed in `DURING PLOT` blocks.

```regia
    DURING backstage:
        WHEN time_to_start:
            WORLD DO dim_lights.
            TRANSITION TO performing.
```

**Execution order during a transition:**
1. Transition event fires (or inline transition is reached), Director evaluates condition
2. `ON EXIT` of the current phase executes
3. Phase belief is updated
4. `ON ENTER` of the new phase executes

### 2.5 Statements by Context

| Statement | In Playbook | In Plot WHEN / ON ENTER / ON EXIT |
|---|---|---|
| `DO action(args).` | ✅ Self-directed | ❌ Use Role DO or WORLD DO |
| `DO TELL(target, msg).` | ✅ | ❌ |
| `DO BROADCAST(msg).` | ✅ | ❌ |
| `DO ACHIEVE(goal).` | ✅ | ❌ |
| `DO BELIEVE(fact).` | ✅ | ❌ |
| `DO FORGET(fact).` | ✅ | ❌ |
| `SIGNAL event(args).` | ✅ To Director | ❌ |
| `WORLD DO action(args).` | ❌ | ✅ Ownerless action |
| `Role DO action(args).` | ❌ | ✅ One-off directive |
| `ASSIGN Playbook TO Role.` | ❌ | ✅ Inject behaviour |
| `UNASSIGN Playbook FROM Role.` | ❌ | ✅ Remove behaviour |

### 2.5 WHEN Block Structure

A WHEN block is either **unconditional** or **conditional**, or a **mix** where unconditional actions prefix every branch:

```regia
# Pure unconditional
WHEN event:
    DO action_a.
    DO action_b.

# Pure conditional
WHEN event:
    IF happy:
        DO greet.
    ELSE:
        DO ignore.

# Mixed: log_event is prepended to every branch
WHEN event:
    DO log_event.
    IF happy:
        DO greet.
    IF angry:
        DO curse.
    ELSE:
        DO ignore.
```

In the mixed form, unconditional DOs must come **before** the IF/ELSE chain.

### 2.6 Conditions

Boolean expressions over FACTs, used inside `IF` guards and `TRANSITION` guards:

```regia
IF happy:                                    # simple fact check
IF NOT angry:                                # negation
IF happy AND has_item(sword):                # conjunction
IF happy OR neutral:                         # disjunction
IF (happy OR neutral) AND NOT busy:          # grouped with parentheses
```

Precedence: `NOT` > `AND` > `OR` (standard). Parentheses override.

### 2.7 Priority Resolution

When multiple plans match the same event on the same agent:

```
Plot one-off directive  >  Playbook plan (by priority number)  >  Default behaviour
```

Higher `PRIORITY` number = higher precedence. Plans without `PRIORITY` default to 0.

## 3. Grammar (Lark EBNF)

```ebnf
// ============================================
// FILE STRUCTURE
// ============================================
program: (import_stmt | element_decl | playbook_def | plot_def)+

import_stmt: "IMPORT" STRING "."

// ============================================
// BASE ELEMENTS
// ============================================
element_decl: action_decl | event_decl | fact_decl

action_decl: "ACTION" ID param_names? "."
event_decl:  "EVENT"  ID event_origin? "."
fact_decl:   "FACT"   ID param_names? "."

param_names:  "(" ID ("," ID)* ")"
event_origin: "SELF" | "ENVIRONMENT"

// ============================================
// PLAYBOOK
// ============================================
playbook_def: "PLAYBOOK" ID ":" pb_when_block+

pb_when_block: "WHEN" ID ("PRIORITY" NUMBER)? ":" pb_when_body
pb_when_body:  pb_stmt* pb_if_branch+ pb_else_branch?
             | pb_stmt+

pb_if_branch:   "IF" condition ":" pb_stmt+
pb_else_branch: "ELSE" ":" pb_stmt+

pb_stmt: do_stmt | signal_stmt

do_stmt:     "DO" action_name arg_list? "."
signal_stmt: "SIGNAL" ID arg_list? "."

action_name: ID | "TELL" | "BROADCAST" | "ACHIEVE" | "BELIEVE" | "FORGET"

arg_list: "(" arg ("," arg)* ")"
arg:      ID | NUMBER

// ============================================
// PLOT
// ============================================
plot_def: "PLOT" ID "." plot_header during_block+
plot_header: (phase_decl | role_decl)+

phase_decl: "PHASE" ID "INITIAL"? "."
role_decl:  "ROLE"  ID "."

during_block:  "DURING" during_target ":" during_content+
during_target: ID | "PLOT"

during_content: transition_stmt | on_enter | on_exit | plot_when_block

transition_stmt: "TRANSITION" "TO" ID "WHEN" ID ("IF" condition)? "."

on_enter: "ON" "ENTER" ":" imperative_stmt+
on_exit:  "ON" "EXIT"  ":" imperative_stmt+

// ============================================
// PLOT WHEN BLOCKS (director-centric)
// ============================================
plot_when_block: "WHEN" ID ("PRIORITY" NUMBER)? ":" plot_when_body
plot_when_body:  imperative_stmt* plot_if_branch+ plot_else_branch?
               | imperative_stmt+

plot_if_branch:   "IF" condition ":" imperative_stmt+
plot_else_branch: "ELSE" ":" imperative_stmt+

// ============================================
// IMPERATIVE STATEMENTS
// ============================================
imperative_stmt: assign_stmt | unassign_stmt | world_do_stmt | role_do_stmt | inline_transition_stmt

assign_stmt:   "ASSIGN"   ID "TO"   ID "."
unassign_stmt: "UNASSIGN" ID "FROM" ID "."
world_do_stmt: "WORLD" "DO" action_name arg_list? "."
role_do_stmt:  ID "DO" action_name arg_list? "."
inline_transition_stmt: "TRANSITION" "TO" ID "."

// ============================================
// CONDITIONS
// ============================================
condition:      condition_and ("OR" condition_and)*
condition_and:  condition_atom ("AND" condition_atom)*
condition_atom: "NOT"? (fact_ref | "(" condition ")")
fact_ref:       ID ("(" arg ("," arg)* ")")?
```

## 4. Architecture

### Compilation Pipeline

```
.rgs source
    |
    |== Parse (Lark LALR) ==================> Lark Tree
    |
    |== Build AST (Transformer) ============> Typed AST (dataclasses)
    |
    |== Validate (semantic checks) =========> Checked AST + errors/warnings
    |
    |== Emit (AST to AgentSpeak) ===========> .asl files
```

### Output Files

| Input | Output |
|---|---|
| Each PLOT | One `director_plotname.asl` file |
| Each ROLE (across all Plots) | One `role_rolename.asl` template file |

The Role template `.asl` contains all Playbook plans that could ever be assigned to it (gated by `playbook_active(Name)` beliefs), plus all one-off directive handlers from every Plot that uses that Role.

### Per-Plot Director

Each active Plot spawns its own Director agent. The Director:
- Manages phase transitions (beliefs: `current_phase(phase)`)
- Executes `WORLD DO` actions (via internal actions / environment API)
- Sends `ASSIGN`/`UNASSIGN` as belief additions/removals to role-bound agents
- Sends `Role DO action` as `.send(agent, achieve, action)` messages
- Receives `SIGNAL` events from agents in assigned Playbooks
- Is created when the Plot starts, destroyed when it ends

### AgentSpeak Mapping

| Regia | AgentSpeak |
|---|---|
| `FACT happy.` | Belief `happy` |
| `FACT has_item(item).` | Belief `has_item(X)` |
| `EVENT fan_greets.` | Trigger `+fan_greets[source(percept)]` |
| `EVENT check SELF.` | Trigger `+check[source(self)]` |
| Playbook plan `WHEN e: DO a.` | `+e : playbook_active(pb) <- a.` |
| `IF happy:` | Context: `: happy` |
| `IF NOT angry:` | Context: `: not angry` |
| `PRIORITY 7` | Plan ordering position in `.asl` file |
| `ASSIGN pb TO role.` | Director: `.send(agent, tell, add_playbook(pb))` |
| `UNASSIGN pb FROM role.` | Director: `.send(agent, tell, remove_playbook(pb))` |
| `WORLD DO action.` | Director: `action` (internal action) |
| `Singer DO ack.` | Director: `.send(singer_agent, achieve, ack)` |
| `SIGNAL emergency.` | Agent: `.send(director, tell, emergency)` |
| `DO TELL(target, msg).` | `.send(target, tell, msg)` |
| `DO BROADCAST(msg).` | `.broadcast(tell, msg)` |
| `DO ACHIEVE(goal).` | `!goal` |
| `DO BELIEVE(fact).` | `+fact` |
| `DO FORGET(fact).` | `-fact` |
| `TRANSITION TO p WHEN e.` | Director plan: `+e : current_phase(old) <- ...` |
| `TRANSITION TO p.` (inline)| Director body: `...` (expands to ON EXIT, belief update, ON ENTER) |

## 5. Full Worked Example

```regia
# =============================================================
# Base Elements
# =============================================================

ACTION greet_back.
ACTION curse.
ACTION ignore.
ACTION flee.
ACTION acknowledge.
ACTION bow.
ACTION perform_song.
ACTION trigger_alarm.
ACTION add_waiting_for_concert.
ACTION announce_concert.
ACTION start_music.

EVENT fan_greets.
EVENT player_asks_about_quest.
EVENT time_to_start.
EVENT emergency.
EVENT song_ends.
EVENT audience_cheers.

FACT happy.
FACT angry.
FACT audience_satisfied.

# =============================================================
# Playbooks
# =============================================================

PLAYBOOK SingerInBackstage:

    WHEN fan_greets:
        IF happy:
            DO greet_back.
        IF angry:
            DO curse.
        ELSE:
            DO ignore.

    WHEN player_asks_about_quest PRIORITY 7:
        DO TELL(player, busy_message).

    WHEN emergency:
        DO flee.
        SIGNAL emergency.

PLAYBOOK SingerOnStage:

    WHEN audience_cheers:
        DO bow.
        DO ACHIEVE(perform_song).

# =============================================================
# Plot
# =============================================================

PLOT Concert.

    PHASE backstage INITIAL.
    PHASE performing.
    PHASE aftermath.

    ROLE Singer.
    ROLE AudienceMember.

    DURING PLOT:
        WHEN emergency PRIORITY 9:
            WORLD DO trigger_alarm.
            Singer DO acknowledge.
            AudienceMember DO acknowledge.

    DURING backstage:

        TRANSITION TO performing WHEN time_to_start.

        ON ENTER:
            ASSIGN SingerInBackstage TO Singer.
            WORLD DO add_waiting_for_concert.

        ON EXIT:
            UNASSIGN SingerInBackstage FROM Singer.
            WORLD DO announce_concert.

    DURING performing:

        TRANSITION TO aftermath WHEN song_ends IF audience_satisfied.

        ON ENTER:
            ASSIGN SingerOnStage TO Singer.
            WORLD DO start_music.

        ON EXIT:
            UNASSIGN SingerOnStage FROM Singer.
```

## 6. Open Questions

### Blocking (for emitter, not grammar)

**Q10: Static gating or dynamic injection for Playbooks?**

How `ASSIGN Playbook TO Role` is realised in AgentSpeak:
- **(a) Static gating**: precompile all possible Playbook plans into every Role template, gated by `playbook_active(Name)`. ASSIGN/UNASSIGN toggles a belief.
- **(b) Dynamic injection**: use Jason's `.add_plan`/`.remove_plan` at runtime.

This does NOT affect the grammar. It affects only the emitter and runtime.
